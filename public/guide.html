Layer-by-layer guide

Five layers, one predictable break

Each toggle on the lab page controls a real contract in the simulated agent. This guide maps those contracts to the exact failure mode they prevent — and to the evidence the lab shows when one is removed.

Honest limits. The simulation is deliberately small. Real agents overlap layers in messy ways; this lab isolates the missing-contract failure so you can see it clearly.

Start here

What this demo proves

Run the same task with all five layers enabled, then disable one layer at a time. Every layer contributes a deterministic step: goal routing, working context, tool call, validation, and user-facing feedback. Remove any one of them and the same request predictably fails.

The five

Cards and missing contracts

Layer 01

Decision

Maps user intent to one tool goal and success criteria. Without it, the agent guesses — often calling search instead of a refund tool.

Proves
the agent routes refunds, searches, and upgrades to the right tool
Key detail
this layer chooses RefundApi.refund_booking, SearchFlights.search, or BookingApi.confirm_upgrade
Layer 02

Memory

Holds working state like booking_id, origin, and destination between layers. Without it, the agent asks for data the user already gave.

Proves
later layers can read the exact booking and trip identifiers
Key detail
memory stores booking_id, currency, and a short history of context
Layer 03

Tools

Executes deterministic services and returns concrete payloads. Tools obey; they do not judge — safety is not their job.

Proves
a refund, search, or upgrade request produces an executable payload
Key detail
the refund tool always issues what it is told — that is the point
Layer 04

Guardrails

Validates budget, routing, and side-effect constraints before completing the action. Without it, the agent executes unsafe operations.

Proves
refunds respect the $2,000 limit and the chosen tool matches the request
Key detail
a $4,200 refund is blocked here — and ships when this layer is off
Layer 05

Feedback

Returns outcome status, evidence, and a user-facing message. Without it, failures stay silent.

Proves
the agent reports completed, blocked, or escalated outcomes
Key detail
every run ends in a message, never a dead end

Run locally

Inspect the evidence

npm start        # serve the lab on :3000
npm test         # domain model + server + e2e
npm run check    # both

Pick Refund an over-limit charge and run it: the guardrails layer blocks the $4,200 request against the $2,000 limit. Now disable Guardrails and run the same task — it completes, and the trace flags the breach that shipped with it.

Limits

What this demo does not claim

  • The simulated tools are deterministic fixtures, not live airline APIs.
  • Real agents mix layers in pipelines, orchestrators, and human handoffs.
  • One missing contract is enough to fail here; in production, failures often overlap multiple layers.
  • A green run means this request passed — it does not prove every request will.
